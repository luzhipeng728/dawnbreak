# 动作手感（跑动 / 攻击顺不顺）

用户反馈（2026-09-29）：“整个角色跑动、攻击动作都还是有些别扭，尤其是跑动的时候。感觉所有角色都是一样。”
所有职业都一样 → 问题在共用层（主循环 / 相机 / 精灵模型 / 动画表），不在某个职业的美术。拿鬼剑士当样本量出来，改在共用层，再用神枪手、魔法师、狂战士（庆典时装）确认。

## 1. 怎么量
| 量什么 | 命令 | 说明 |
|---|---|---|
| 逐步体检 | `WEB=1 node test/animfeel.mjs sword <输出名> [--pace] [--town] [--look=festival]`（职业可写 `sword:berserker`；约 6 秒） | 停掉 rAF，按 60Hz 逻辑步驱动固定输入：走 → 停 → 双击跑 → 停 → 反向跑 → 跑中转身 → 跳 → 普攻 1~3 → 跑攻。每步记状态 / 所画的帧 / 头部锚点（含下面的修正）/ 贴地的脚，出指标 JSON 和逐步连拍 `test/shots/animfeel/<名>_<段>.png`（每格一个逻辑步） |

指标：`holdHist / holdCV` 每张帧停留几个逻辑步（CV 0 = 节奏均匀）；`headJumpMax` 头部（相对实体锚点）每个逻辑步的最大位移 = 身体“瞬移”；`headBobY / headSwayX` 跑步中头部上下 / 前后的范围；`strideMatch` 贴地的脚在画面里被“蹬过去”的距离 ÷ 同期身体走的距离（1 = 脚钉在地上，< 1 = 脚往前滑）；`camAccMax` 相机每步滚动量的最大变化（相机甩一下）；`bgErrRms` 画面背景位置对匀速的误差（像素）。

## 2. 发现（鬼剑士，测试房间 = 地下城；城镇同一套代码）
1. **固定步长不插值（最大，所有画面都受影响）**：逻辑 60Hz，画面直接画最新一步。显示器刷新和逻辑步对不齐（时间戳抖动 0.3ms 就够、120Hz 隔帧画、144 / 90 / 75Hz、偶尔掉帧）时，会有“这一帧 0 步、下一帧 2 步”：60Hz 抖动下 45% 的画面不是正好 1 步，跑动时背景对匀速的误差 2.6 像素（均方根，最大 4.2），速度突变 p95 = 2 倍。这就是“跑起来一顿一顿”。
2. **跑步节奏发瘸**：跑 8 帧 16.7fps = 每帧停 3 / 4 步交替（CV 0.14）；走 10fps 均匀。
3. **跑步身体一跳一跳**：美术帧第 3、7 帧突然站直、头部上跳 6~7 像素（其它帧前倾），下一帧又落回去——单帧尖刺，不是均匀起伏；前后也晃 3.8 像素（剑士），魔法师类似（5.5），神枪手轻一些（2.8）。三个职业的跑步表都是同一套姿势参考生成的，问题一样。
4. **脚底打滑**：跑步美术步幅偏短，脚被“蹬过去”的距离只有身体走的 0.47~0.56；走路 0.41~0.77。
5. **普攻 / 跑攻身体瞬移**：动作帧的锚点（`frames2.py` 按躯干 / 脚下像素中位数取）一帧落在后脚、一帧落在前脚，换帧时身体水平跳：剑士普攻 1 起手 → 挥砍头部往后跳 29 像素、普攻 2 跳 26、魔法师普攻 1 往前 27、普攻 2 往后 39、神枪手射击 18。
6. **转身相机甩一下**：相机目标带 ±70 的朝向前瞻，转身瞬间目标跳 140 像素，相机速度突变（每步滚动量变化 11.9 像素）。
7. 已排除：时装 / 武器 / 配件层和身体同一次 `draw` 取同一帧（`AvatarLayer.frame(m, f)`），不会晚一帧；受击停顿时动画和位移一起冻结；起停没有加减速是官方手感，没动。

## 3. 改了什么（全在共用层，不改移速 / 攻速 / 判定 / 技能）
1. **渲染插值**（game/game.js `snapPrev / lerpIn / lerpOut`）：每个逻辑步开始记下实体 / 投射物 / 城镇路人和相机的上一步位置，画的时候按 `acc` 插到两步之间，画完（世界层 + 界面层）立刻换回真实位置；一步移动超过 48 像素（瞬移 / 换房间）或相机超过 120 的不插值。逻辑、联机、测试读到的永远是真实位置。
2. **走 / 跑节奏 + 速度联动**（content/sprites.js、`SpriteModel.loopRate`、engine/entity.js、game/world.js 路人）：走 12fps（每帧 5 步）、跑 20fps（每帧 3 步），`v` = 职业基础移速；实际速度（移速装备 / BUFF、城镇移速、路人）不同时按比例加减速，每帧停留步数取整（节奏始终均匀），最少 2 步。顺手修：循环动作的骨骼片段时长和“帧数 / fps”对不上时会在一圈中间绕回第 1 帧，现在统一成帧数 / fps。协战师战斗服的走 / 跑改用神枪手同一套。
3. **跑 / 走的身体起伏归一**（models/imgmodel.js `sprLoopNorm`）：按原装帧的头部锚点把一圈的头部轨迹拟合成“每步一次”的正弦（均值 + 二次谐波，前倾起伏再减半），每帧绕脚底做竖向压缩（≤ 6%）+ 水平错切（≤ 0.08）把头对上：脚不离地，时装 / 武器 / 配件跟着一起变。没有头部锚点的模型（怪物）不处理。
4. **换帧缓动**（`SpriteModel.ease`）：换帧时把头部的水平跳动记成偏移，按指数衰减（k = 28/秒，约 0.1 秒）收回 0；最后仍停在原锚点，判定 / 特效位置不变。循环动作内部、受击 / 浮空 / 倒地类片段、转身、跳动超过 40 像素的（跳斩起跳 / 落地、冲刺这类本来就是换姿势）照旧直接换帧。
5. **相机前瞻平滑**（`updateCamera`）：朝向前瞻 `cam.look` 先平滑一层再给相机，转身时相机速度连续变化。

## 5. 还需要美术的（代码补不了的部分）
- **跑步步幅短**：修完仍只有 0.57~0.66，脚还会往前滑。要到 1 需要 30fps（每帧 2 步）的碎步，太急；正解是重画跑步：腿伸得更开（接触帧前后脚距离约 1.5 倍），8 帧里第 3、7 帧画成真正的腾空帧（现在是站直的过渡帧）。
- **普攻的锚点**：跳斩（普攻 3）起跳 / 落地、跑攻这类 40 像素以上的跳动没有缓动，照旧换帧。根治要把动作帧按“后脚不动”重新对齐锚点（原装 + 6 套时装同名帧一起平移，武器轨迹 / 头部锚点 / 分割线都是帧内像素坐标，不受影响），但各技能的特效偏移是对着现在的锚点调的，要逐个技能复查，属于美术 + 技能组一起做的活。
- 普攻起手只有 2~3 个逻辑步（a1_1 0.05 秒）是动作时间轴决定的，没改（改了会影响手感和判定）。
