# 性能与卡顿排查（渲染帧率 / 网络 / 服务端）

用户反馈（2026-09-29）：“和好友玩了下，好像有点卡”。先量再改：帧率、网络、服务端、城镇、决斗操作延迟分开测，按数据排出瓶颈。

## 1. 怎么量（命令都可以直接重跑）
| 量什么 | 命令 | 说明 |

## 2. 结论（2026-09-29 实测）
**卡顿主要来自渲染（大范围技能同时打中一屋子怪），其次是决斗里对方的操作延迟；带宽和服务端都不是问题。**

1. **渲染（最大）**：技能范围放大后，一次施放同时打中十几二十只怪，每只怪都在“受击闪白”。闪白 / 霸体描边原来是每只怪各自画进 720×680 的离屏缓冲 → 复制到第二张着色 → 合成到第三张 → 再画回世界层，每一步都要先把源画布的绘制命令冲刷掉；CPU 采样里这一项（`Ent.draw`）占忙碌时间 15~16%，是第一大热点，最慢的帧里它一项就 11~20ms。第二是伤害数字：每帧每个数字都 `toLocaleString`（每次新建格式化器，`fmtNum` 单独占 5~8%）、换字号、描边、建渐变，同屏 100~170 个数字。
2. **决斗**：对方按键要等 主机→对方 一个完整来回才看到自己出招：本机 60ms、往返 60ms 时 178ms、往返 120ms 时 295ms。详见 NETWORK.md「决斗的操作延迟」。
3. **网络量很小**：2 人组队、满房间打，队长上行约 15~17KB/s（快照 `s` 20Hz × 约 560B 占 2/3，`spawn` 1.6 次/秒 × 1.5~2KB，`kill` 15 次/秒 × 62B，`p` 20Hz × 130B），队员上行约 6KB/s（`p` 20Hz、`hb` 命中包 3~6 次/秒 × 400~800B）。单条最大 3.8KB。每秒 50~60 条，离服务端限流（150 条/秒）还远；客户端处理所有收到的消息每秒只要 2~5ms（CPU ×4）。不需要做快照增量 / 量化。
4. **线上链路**：本机到 cc 的 ICMP 往返 42ms（抖动 0.35ms）；HTTPS `/api/health`：TCP 43ms、TLS 90ms、首字节 131~138ms，首字节 − TLS ≈ 一个往返，Caddy + 服务端处理几乎为 0。队友之间一次转发 = 两人各自到服务器的半个往返之和。
5. **服务端**：本机压测 20 间组队房（×2 人）+ 城镇 20 人：CPU 8.6%、事件循环延迟 p99 1.8ms（含 1ms 采样间隔）；25 间 × 4 人：CPU 12.5%、p99 2.4ms；50 间 × 2 人 + 城镇 50 人：CPU 22%、p99 8.8ms、偶尔 40ms——这档的大头是城镇 50 人互相广播位置（N² = 每秒 2.4 万条）。现在同时在线的人数远用不到，不用改。
6. **城镇**：4 人同场景来回走，CPU ×4 下 60fps、1% low 59.5，每人收发 < 1KB/s。
7. **在线更新轮询**：每 60 秒拉一次 `version.json`（333 字节），可以忽略，没改。
8. **抖动**：原来按到达时间插值，抖动 0~150ms 时队友影子速度波动 0.45（队长自己跑是 0.34）、偶尔跳帧；改成按发送方帧时间插值后 0.31、不跳帧。实际影响不大，属于顺手修。

## 3. 改了什么（都没动数值和技能行为）
- `engine/entity.js` + `models/imgmodel.js`：怪物（没有外观层的精灵帧模型）的受击闪白 / 霸体描边直接画到世界层——描边 = 4 个偏移的纯色剪影，闪白 = 再叠一层 0.7 的白色剪影；剪影按（帧图, 颜色）缓存（`sprSil`，最多 96 张帧图，最久没用的释放）。职业角色（武器光效 / 转职特效会超出帧图）仍走原来的离屏合成（同屏 1~4 个）。像素对比：和原来差异平均每像素 < 1.6/765、没有明显差异的像素。
- `engine/fx.js`：伤害数字改成字形图集（每种字号 × 描边色 × 填充一张，数字 + 逗号，描边层 / 填充层分开贴，效果同 strokeText + fillText），格式化后的字符串缓存在数字上。稳定后和原来逐像素几乎一致；弹出的前 80ms 描边跟着放大（原来描边宽度不变），肉眼看不出。
- `engine/core.js`：`fmtNum` 用缓存的 `Intl.NumberFormat`（输出和 `toLocaleString('en-US')` 完全一样）。
- `net/coop.js`：`s` / `p` 带发送方帧时间 `ts`，接收方按它插值（`netClock`：偏移取最小值、慢慢放宽，插值延迟 = max(100ms, 发送间隔 + 一帧 + 抖动)）。
- `net/pvp.js`：决斗对方的角色改成本地模拟 + 主机裁决（NETWORK.md）。

## 5. 以后
- 世界层剩下的大头是职业角色本身（外观层：武器光效、转职特效）和技能特效，各 0.5~1ms / 帧（CPU ×4）；界面层每帧重画所有 HUD 文字约 1.4ms（CPU ×4），要再压可以把不变的文字缓存成图。
- CPU 采样里 `(program)`（画布栅格化 / 提交等原生部分）占忙碌时间 35~40%，无头浏览器的 GPU 配置和真机不同，这部分在真机上要用 `test/bench.mjs`（Metal、1728×962@2）看。
- 城镇人多了（几十人同场景）要做兴趣范围 / 降频：服务端 N² 广播。
