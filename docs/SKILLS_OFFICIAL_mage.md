#### 招牌机制（要做对手感，这几条最关键）

1. **蓄气**：大多数技能是“按住蓄气、松开发射”。2017 年以后蓄气只影响大小和范围，不影响伤害；只有决斗场里蓄气仍然加伤害【高】。
   - 本作现在是蓄气加伤害（`charge.dmg`），建议 PvE 改成只放大范围，决斗场保留加伤。
2. **移动施法**：蓄气时可以走动和冲刺，这是元素师的核心手感。
   - 引擎需要支持“蓄气中移动”：`act.charge.move = 速度倍率`。
   - 实现上：蓄气期间不锁住 `vx`/`vy`，走跑动画上叠一个举杖的上半身；最简单的做法是出一套 4～6 帧的“举杖走”循环。
3. **元素点燃**：连续放不同属性的技能会点亮标记，标记越多伤害加成越高。它奖励的是在四个属性之间轮换出招，而不是一直放同一个属性。
4. **魔法秀 + 魔法记忆**：减少蓄气和施法时间。二觉以后蓄气时间能压到 0（玩家叫“无充”）。
5. **四属性**：元素师**没有切换属性的技能**，每个技能的属性是固定的。多属性技能按“攻方属强 − 目标抗性”最高的那个属性结算。

   本作的 `elemMul` 每次只取一个属性，需要加一个 `elems: [...]` 取最优（改动很小，放在 combat.js）。
6. **澄清两个误解**：
   - “元素爆破”是男法的转职（元素爆破师），不是元素师的机制【高】。
   - 按住 X 自动射魔法球是手游《起源》的设计，端游没有【高】。

#### 召唤物的全局规则（直接决定框架设计）【高】

- **数值**：召唤兽的 HP 和防御在召出那一刻按本体比例取快照；**魔攻、智力、属强、魔暴与本体实时共享**。召唤兽吃光环、狂化、鞭挞、跟随这些增益。
- **能否被打**：2024-09 起（韩服），地下城里所有召唤兽都**打不到**；决斗场里召唤兽有自己的 HP，能被打死，也会中异常状态。
- **本体死亡**：全部召唤兽消失。
- **在场时间**：
  - 契约兽、上级精灵、精灵王、海伊伦：无限。
  - 下级精灵：30s。
  - 卡西利亚斯、拉莫斯、赫德尔：200s。
- **数量**：每种召唤兽同时只能有 1 只（下级精灵是 4 种各 1 只）。全部召齐时场上大约有 17 只。超出上限时，先驱散剩余时间最短的那只。
- **AI**：每只召唤兽有自己的好战度、视野、移速、攻速，每个招式有独立冷却；会优先用伤害高的招式，主动去找怪。召唤兽的攻击冷却**不吃**本体的冷却缩减。
- **换房间**：召唤兽跟着本体进下一个房间，袄索从本体面前的地面钻出来。
- **再按一次召唤键**（契约兽叫交感，精灵叫附灵）：召唤兽瞬移到本体前方，放出专属招式；按住 ↓ 再按键则瞬移到本体脚下。追加指令有独立的冷却和 MP 消耗（约为召唤时 MP 的 20%）。召唤兽在场时，技能图标会变绿。
- **咒令**：必须有指定的召唤兽在场才能施放。
- **全体指令**：跟随、传送、伺机而动（全体停手）、解除、魔力印记（集火）、支配之环（一键召唤）。
- **装备特效**：召唤兽的攻击触发“攻击时”类装备特效的概率只有 1/10；追加指令算作“施放技能”。

#### 招牌机制

1. **成功率系统**【高】
   - 结果分三档：失败 / 成功 / 大成功。二觉以后变成：失败 / 大成功 / 超大成功。
   - 施放时，对应的使魔会在头顶弹出一个表情，展示这次的结果（4 只使魔 × 4 档，共 16 个小图标）。
   - 不同档位的差别很大：范围、段数、会不会浮空、附加的异常状态都不一样。
   - 被动堆高以后几乎必定大成功；苦涩的棒棒糖反过来让玩家“主动选择失败”，换一次爆发。
   - **失败的搞笑动画（熏黑、摔跤、触电）就是这个职业的卖点。**
   - 本作可以在框架里加一个 `rollCraft(p, id)` → `'fail' | 'ok' | 'great' | 'super'`，头顶弹出表情用 fx 图标。“熏黑”用 `spr.json` 的头部锚点叠一张煤灰贴图即可，不需要另出帧。
2. **属性**
   - 现版：属性按使魔系固定。
   - 经典版：技能是无属性的，大成功才变成对应属性。
   - 建议用现版。
3. **扫把飞行**：需要通用组支持一种新的空中状态，要求包括：
   - 空中 6 连击；
   - 2 次空中冲刺；
   - 2 次缓降；
   - 施放技能后刷新冲刺次数；
   - 空中施放技能时按 120° 扇形判定。
4. **搭乘机械**（炉子、电塔、冰车、光电兔）
   - 流程是：组装 → 搭乘 → 持续输出 → 爆炸。
   - 搭乘期间免疫异常状态，受到的伤害 −60%。按跳跃（引爆实验）可以取消并引爆。
   - 本作做法：主角画进机械的精灵图里，搭乘期间主角实体隐藏或固定在机械上；机械本身用召唤框架的 follower 来做。

#### 转职剧情【高】

- **背景**：魔界博隆克斯的“人偶之森”，每棵树都是魔法陷阱，紫雾会让人一步步忘记自己；森林中心有一座“暗宅”，传说濒死的人去过暗宅后获得了新生。
- **一觉独白**：“当当当当！就是把你做成我的人偶！……你会死去，但别怕，我一定会把你重新唤醒。记得要梦到我哟！”病娇感很强。
- **转职任务**：官方 2019 年上线时就没有经典的转职任务。
  - 本作可以自己设计：导师莎兰指引，去冰霜幽暗密林深处的迷雾里找到“暗宅”。【建议】
- **外观**：哥特洛丽塔，脸和膝盖上有缝合伤口；二觉右眼被缝上。官方为她单独加了 4 个动作：举手“万岁”、缝纫、抱人偶、捂耳朵。

### 6.2 三种形态

| kind | 是什么 | 实现 |
|---|---|---|
| `follower` | 有身体、有动作、有 AI 的伙伴实体 | `Ent`：`summon: true`、`owner`，放进 `ents`，和其他实体一起按 y 排序绘制；模型用 `SpriteModel`，和怪物是同一条 `spr.json` 流水线 |
| `field` | 地面上的定点区域，按间隔结算 | 纯数据对象。地面图案画在地面层；站立形象（鬼神、明王）用 `drawUpright` 进同帧的排序列表 |
| `attach` | 挂在某个实体（敌人或自己）身上的持续效果 | 纯数据对象，跟着宿主走；宿主死亡、被移除或离开房间时自动结束 |

### 6.3 接口

```js
defSummon(key, {
  kind: 'follower' | 'field' | 'attach',
  tags: ['spirit', 'lesser'],   // 分组：献祭下级精灵、G 系共享时间、精灵王光环……
  max: 1,                       // 同一 owner、同一 key 的上限
  tagMax: { gseries: 3 },       // 同一 owner、同一 tag 的上限
  over: 'oldest',               // 到上限时：'oldest' 挤掉剩余时间最短的 | 'refresh' 刷新时间 | 'deny' 放不出
  life: 20,                     // 秒；Infinity = 常驻
  keepRoom: undefined,          // 换房间时是否跟着 owner；默认 follower = true，field / attach = false
  // ---- follower ----
  model, clips, w, d, h, scale, fly,      // fly = 悬浮高度
  speed, pref, aggro, sight,              // 移速、保持距离、好战度、视野
  attacks: [...],                         // 与 MON[kind].attacks 同格式 { clip, range, dy, cd, act }，每招独立冷却
  ai: (s, dt) => {},                      // 省略 = 默认 AI（6.6）
  cmds: { special(s, arg) {}, explode(s) {}, recall(s) {} },
  hp: owner => owner.hpMax * 0.4,         // 省略 = 不能被攻击（invul = Infinity，敌人的攻击和投射物直接穿过）；也可以只在决斗场里启用
  enterAt: 'behind' | 'front',            // 进新房间时出现在 owner 身后还是身前（袄索从面前钻出）
  // ---- field ----
  r: 80,                        // 半径（或写 box）
  tick: 0.5, onTick(s, foes),   // foes = 范围内可以命中的敌人
  drawUpright(c, s),            // 可选：站立形象，按 y 排序
  // ---- attach ----
  host: 'target' | 'owner',
  tick: 0.5, hits: 10, onTick(s, host),
  // ---- 通用 ----
  onSpawn(s), onEnd(s, why),    // why: 'life' | 'dead' | 'replaced' | 'room' | 'owner' | 'cmd' | 'round'
  draw(c, s),                   // field 画在地面层；attach 画在宿主身上；follower 用模型
});

summon(owner, key, { x, y, at: 'front' | 'feet', target, lv, life, mul })  // → 句柄 s（follower 就是 Ent）；任何代码都能调用，不需要施法动作
summonsOf(owner, key | { tag })                 // → 数组
summonCmd(owner, key | { tag }, cmd, arg)       // → 执行命令的召唤物数量
dismissSummons(owner, key | { tag } | undefined, why)   // 不传 key = 清掉这个 owner 的全部召唤物
clearAllSummons(why)                            // 决斗换回合、离开地下城时用
summonHit(s, t, h, o), summonArea(s, x, y, r, h, o)     // field / attach 造成伤害的入口；o.hitGroup 可选
hitGroup()                                      // 共享的“已命中”表：同组内同一个目标只结算一次（剑影共鸣）
s.warp(x, y, z)                                 // follower 瞬移，同时清掉速度
summonAct(s, act)                               // follower：打断当前动作，再执行 act（打断时会调用 onEnd(…, true)）
strongestFoe(s, range), summonsIn(owner, x, y, r)       // 找最强的敌人；找范围内自己的召唤物（鞭挞、月蚀之影）
owner.summonMode = { follow, hold, mark }       // 全体开关：跟随、伺机而动（停火）、魔力印记（集火目标）
rollCraft(p, id)                                // 魔道学者：'fail' | 'ok' | 'great' | 'super'，头顶弹出使魔表情
```

### 6.4 伤害与数值

- **follower**：
  - 身上的 `atk` `matk` `indep` `crit` `mcrit` `critDmg` `hitRate` `dmgUp` `atkElem` `lvl` 都是**读 owner 的 getter**，而且已经算上了 owner 的 BUFF。官方就是这样：魔攻、智力、属强、魔暴与本体实时共享。
  - 召唤物自己**另有**一个 `buffs` 对象，只放作用在召唤物身上的增益：鞭挞、狂化、召唤兽强化光环、精灵王光环。
  - 所以召唤物自己动作里的 `act.hits`、它自己发的 `spawnProj({ owner: s })`，都照常走 `applyHit`，**引擎不用改**。
  - HP 和防御在召出那一刻按 owner 的比例取一次快照。
- **field / attach**：调用 `applyHit(owner, t, h, { proj: true, src: s })`。
  - 伤害按 owner 的面板算。
  - 打击停顿只给目标。
  - 职业命中钩子收到的 `act` 是 null，所以不会顺带生成炫纹、触发出血。
- **技能等级成长**：写在 `h.dmg` 里（`skillDmg(基础, 每级, lv)`），召出时把技能等级存进 `s.lv`。
- **连击**：召唤物和 owner 是同一个 team，命中照常计入连击。
- **装备“攻击时”特效**：官方的召唤物只有 1/10 的概率触发。需要主线程在 `playerHit` 事件里带上 `summon: true`，再由装备组（`gear_fx.js`）按这个概率处理。
- **联机**：
  - 召唤物由 owner 所在的客户端模拟。
  - `net/coop.js` 的 `localHit` 已经接受 `a.owner === game.player`，所以队员的召唤物和阵打到怪，伤害会自动报给主机。
  - 主机那边能看到队员的召唤物属于 P2，需要联机组在快照里加上召唤物列表。

### 6.5 生命周期

- **换房间**：
  - 用 `game.room` 对象是否变化来判断（`roomEnter` 事件只在第一次进房时发）。
  - follower 默认跟着 owner 进新房间，按 `enterAt` 放到 owner 身后或身前。
  - field / attach 清掉。
- **owner 死亡或离场**：他的召唤物全部消失（`why = 'owner'`）。
  - 决斗换回合时，`duel.js` 会清空 `ents`，框架会顺带把没有 owner 的召唤物清掉；也可以直接调用 `clearAllSummons('round')`。
- **到期或被打死**：先播放消散特效，然后标记 `remove = true`，再调用 `onEnd`。
  - `game.js` 本身不清理死亡的 team `'p'` 实体，所以这件事由框架自己负责。
- **遍历安全**：每帧遍历的是快照。新召出的召唤物从下一帧才开始 tick；删除只做标记，到帧末再统一清理。所以在 `onTick` 里可以直接 `summon` / `dismiss`（罗刹就是先 field，踩到后变成 attach）。

### 6.6 默认 AI（follower）

1. **没有敌人**：
   - 跟在 owner 身后 50～80px，纵深对齐；owner 跑起来时同速跟上。
   - 离 owner 超过 500px 就直接闪现到他身边。
   - 开着“跟随”时，范围收紧到 100px 以内。
2. **有敌人**：
   - 目标优先级：集火标记 `summonMode.mark` → 离自己最近的敌人。
   - 走到 `pref` 距离，冷却好了就按权重出招；伤害高的招式优先。
   - 召唤物的攻击冷却**不吃** owner 的冷却缩减。
3. **伺机而动**（`summonMode.hold`）：原地停手，只执行命令。
4. **收到命令**：`cmds[name]` 直接接管，做完再回到默认 AI。

### 6.7 再按技能键下命令（recast）

- **技能字段**：`recast: { ok(p), cd, mp, act(lv, p) }`。
  - 召唤物在场时再按这个技能键，就执行 recast。
  - recast 有独立的冷却，存在 `p.cool[id + '~']` 里。
  - “按住 ↓ 再按”的变体，由 `act` 自己读 `p.pad.dy()` 判断。
- **用到它的地方**：
  - 召唤师的交感 / 附灵；
  - 冰墙撤掉、湮灭黑洞提前引爆、炫纹簇引爆；
  - 机械师的引爆 / 召回；
  - 剑影的幻鬼出招。
- **改动点**：
  - `game/player.js` 的 `castSkill`：在冷却检查之前插入约 4 行，由通用组来改。
  - 技能栏上“可以再按”的绿框：画在 `ui/hud.js`（界面组）。
- **决斗场 AI**：技能写 `ai.summon = key`；如果 `summonsOf(p, key)` 已经到上限，就不再放这个技能，有 recast 的话改用 recast。改在 `game/fighter_ai.js`，由通用组来改。

## 8. 需要用户拍板的问题

1. **战斗法师照哪一版做？**
   - 建议：**现版（2024 重做后）**。用户要求“和官方一致”，而现版就是现在的官方。旧版的五属性炫纹早在 2018 年就合并掉了。
   - 代价：重做炫纹系统和 4 个技能，觉醒从“变身贝亚娜”换成“星纹陨爆”（现有的 bmAwk 帧和插图还能复用）。
2. **魔法护盾用现版（防御 BUFF）还是旧版（MP 抵伤）？** 建议用现版。
3. **普攻第 3 下改成近战、跳攻改成挥杖**，也就是去掉现在的“发魔力弹”。**确认改吗？** 用户和主线程提到的“魔法球自动攻击 / 扫把跳攻”在官方里分别属于男法 / 手游、魔道学者，女法本体没有。
4. **P0 的范围**：
   - 是否按“官方 Lv1～48 的全部主动 + 被动”来做？这个范围对应本作 Lv1～21。
   - 还是先只做主动技能，被动放到后面？
5. **召唤师 P0 需要 11 只新召唤兽的美术**（约 40 次生图）。能不能先用“参考图 + 1 张动作表”的简版（每只 2 次，合计约 22 次）上线，之后再补？
6. **新动作帧的时装版本**：P0 是否先不出（时装缺帧的那几帧会闪回原皮），P2 再统一补？
7. **转职任务**：沿用现在“七次修炼 + 在导师处选择”的流程，还是每个转职单独加一步专属试炼（例如元素师的四元素信物）？建议 P2 再做。
8. **小魔女照哪一版做？**
   - 国服 2026-01 删掉了诅咒人偶资源，改成冷却制；韩服仍保留人偶资源。
   - 建议：国服冷却制 + 韩服的“单刷模式”（单人时自动偏爱疯疯熊、熊技能加伤、冷却 −20%）。否则她作为辅助职业，单人几乎打不出伤害。
9. **魔道学者的成功率系统**：失败会“熏黑 / 摔跤 / 触电”，这是官方的卖点，但失败会让伤害变低。是否照搬？建议照搬：P0 就放进苦涩的棒棒糖（主动选择失败），被动升级后成功率很高。
